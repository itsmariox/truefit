# Skills (the agents' instructions)

The agents' instructions, written so they name no person, employer or place. They replaced the original skills in the step 7b cutover. A skill is edited as plain text; code never rewrites it.

## What code must supply (the contract for step 7)
Blocks are passed to the model as `<name>...</name>`. `<profile>` is `profileToPersona(profile).text`, which already carries its own `<profile>` tags. The Rules section of `<profile>` has these lines, which the skills quote by name: Salary floor, Based in (with Wants and Work modes), Allowed CV location lines, Seniority (with Avoid), Right to work, Roles to avoid, and, only when the user filled it in, Availability.

| Skill | Agent | Blocks it expects |
|---|---|---|
| fit-analysis | Analyst | `job_ad`, `profile` |
| cv-writing | Writer | `job_ad`, `analysis`, `profile`, `limits`, `checker_problems` (optional) |
| fact-check | Checker | `summary_to_check`, `cv_text`, `profile`; in text mode `text_to_check`, `profile` |
| coach-reply | Coach | `tone` (friendly, neutral or concise), `team_results`, and the mode name |
| cover-note, recruiter-message | Coach | `job_ad`, `profile`, `team_results`, `checker_problems` (optional) |
| interview-prep | Coach | `job_ad`, `profile`, `stories`, `team_results`, `checker_problems` (optional) |
| company-brief | Coach (research) | `job_ad` ONLY. No profile, no `team_results` (in the old code it also received the analysis: strengths, evidence quotes and gaps drawn from the profile, which is personal data going into a web search; the cutover removes it), no `limits` |
| cv-import | Importer | `cv` (the CV text with contact details removed) |
| humanizer | Coach | appended to the Coach's instructions, unchanged |

`<limits>` is generated by code from `selectionBudget` (src/cv/selection.ts): the number of achievements, each role id with its title, company, bullet range and **the list of usable bullet ids for the chosen focus type** (so the Writer cannot pick a bullet restricted to another focus type, which code would reject and burn the single fix round), the skills range, and the summary length (20 to 70 words, 2 or 3 sentences).

## Schema changes the cutover made (now in src/agents/schemas.ts)
- **Analyst:** `archetype_id` becomes `focus_id` (number or null); `archetype_note` becomes `focus_note`. Everything else keeps its name (`unverified_needed` now means "tools or skills the ad asks for that the profile does not show").
- **Writer:** the output becomes `CvSelection` (src/cv/selection.ts): `focus_id`, `summary`, `achievements[{id, bold}]`, `roles[{role, bullets[]}]` for every listed role, `skills[]` (one ordered list), `questions[]`, `notes`. The two fixed employer lists and the three fixed skill lists of the old schema go away.
- **Checker:** unchanged fields (`claims`, `rule_breaks`, `verdict`). The `approved_template_wording` block goes away (the template has no fixed wording). The text mode is now inside the skill, so agent.ts no longer appends it.
- **Coach:** receives `<tone>` from Settings. The question message no longer says "add it to persona/ and press Retry": the app shows an answer box (PRD 08).

## Cutover must-haves (step 7b): ALL DONE, each with a test
1. (done: `pipeline.test`, `scanText` in `src/cv/selection.ts`) **Do-not-use must be enforced on every extra, not only on the CV summary.** The only code check today is `validateSummary`, which runs on the summary alone. Cover notes, recruiter messages and interview answers are free text from the Coach, which never sees the Do-not-use list, and the text-mode Checker does not see it either. Before delivery, run the same term scan (forbidden phrases, removed skills, known gaps, residence) on the text of every extra, and send a hit back as `checker_problems` (one rewrite, as today).
2. (done: `agent.ts` is deleted; the prompt builders are `src/agents/prompts.ts`) **Delete the inline prompts in agent.ts** that these skills replace: the text-mode paragraph appended to the Checker's instructions (it is now the skill's "Text mode" section, including the time-word rule and the skip rule for statements about the company or the candidate's opinions) and the "Your previous ... had claims the Checker could not back" line (now the "If `<checker_problems>` is present" section of the three checked extras). The user messages that name the candidate in agent.ts must say "the candidate".
3. (done: `agents.test`) **Company brief gets the job ad only** (see the table).
4. (done: `src/cv/limits.ts`) `<limits>` lists usable bullet ids per role (see above).

## Deliberately NOT in the skills
Do-not-use phrases, removed skills, known gaps and draft items are enforced by code and never shown to any agent (decision 2026-11-16), so no skill lists them. A rejection arrives in `<checker_problems>` and the skill tells the Writer to replace the flagged item.
